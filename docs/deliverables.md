# PDF Deliverables Checklist (MiniRAFT.pdf)

This document maps the PDF submission requirements to the current repository.

## A. Source Code Repository

PDF expects a repo containing:
- Gateway service
- 3 replica nodes
- Frontend service
- `docker-compose.yml`
- Logs demonstrating failover events

Where these are in this repo:
- Gateway: `services/gateway`
- Replicas: `services/replica` (instantiated 3x via Docker Compose: `replica1`, `replica2`, `replica3`)
- Frontend: `services/frontend`
- Compose: `docker-compose.yml`
- Logs: emitted as JSON to stdout by replicas and gateway; see `docs/testing.md` (“Capturing Logs”).

Note: The PDF lists folders like `/replica1`, `/replica2`, `/replica3`. This repo uses one replica codebase (`services/replica`) and runs three containers with distinct environment variables.

## B. Architecture Document (2–3 pages)

See `docs/architecture.md`, which includes:
- Cluster diagram (Mermaid)
- RAFT-lite protocol notes
- State transition diagram (Mermaid)
- API definitions (Replica + Gateway)
- Failure-handling design

## C. Demonstration Video (8–10 minutes)

This deliverable can’t be generated by code changes.

Suggested demo script (matches PDF bullet list):
1. Open `http://localhost:3000` in 2+ tabs and draw.
2. Kill the leader replica container (observe uninterrupted drawing).
3. Show automatic failover (new leader in `/status`).
4. Edit a replica source file to trigger hot reload (process restart inside container).
5. Restart a replica with cleared state and show catch-up via `/sync-log`.
6. Stress: rapid restarts while drawing.

## Docker & Deployment Requirements

- 3 replicas + 1 gateway + 1 frontend: `docker-compose.yml`
- Bind-mounted source folders: compose `volumes:` for `services/*/src` and `shared/src`
- Healthy startup ordering: compose `depends_on: condition: service_healthy`
- Hot reload: `node --watch` used by `npm run dev` in each container

## Testing & Verification

- Integration test: `npm run test:integration`
